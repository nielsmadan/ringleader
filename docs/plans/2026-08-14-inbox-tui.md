# Inbox TUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `rl roundup` (refresh + prune + enrich) and `rl inbox` — a Textual inbox-zero TUI for blitzing dormant sessions with `j`/`k` + per-session harvest / delete / snooze / select-for-today.

**Architecture:** Deterministic support first (`roundup`, a fuzzy-duration parser, a notify helper, a `selectedForDay` registry field), then the Textual app under `ringleader/inbox/`, launched by `rl inbox`, importing internals in-process. Textual is an optional `ringleader[tui]` extra. The app is tested headlessly with Textual's `Pilot`.

**Tech Stack:** Python ≥3.13; Textual (optional `[tui]`); the existing registry / `refresh` / `prune` / `enrich` / `harvest` / `snooze` internals; `pytest` (+ Textual `Pilot`), `ruff`.

## Global Constraints

- **Reuse, don't rebuild.** `roundup` composes `refresh.auto_refresh`, an extracted prune-delete helper, and `enrich.cmd_enrich`. The TUI calls existing registry mutators (`snooze_thread`, `mark_harvested`, `archive_session`, `select_for_day`) and command flows (`harvest`, `complete`) — it does not reimplement them.
- **No new *required* dependency.** `pyproject.toml` `dependencies` stays `[]`; Textual goes under `[project.optional-dependencies]` as `tui`. `rl inbox` fails with a clear "install ringleader[tui]" message if Textual is absent; everything else works without it.
- **`roundup`'s prune deletes** tiny+stale (reuses `prune_candidates` + the extracted delete helper), gated behind the inbox pre-flight *y* or an explicit `rl roundup` run; reports the count.
- **Conditional archive on harvest:** a harvest yielding nothing durable (empty summary + no gotchas/decisions/whatChanged) → archive the session immediately; else it stays live in the harvesting tab.
- **Delete is staged with undo, applied on exit.** Harvest/snooze/select apply immediately.
- **Tests never call a real model, scan real data, or write real state.** Mock the Model seam; tmp registry + `XDG_DATA_HOME`; mock `osascript`. TUI tests use Textual `Pilot`.
- Tests pass with `uv run pytest -q`; `uv run ruff check` and `uv run ruff format --check` clean.

- [ ] **Step 3: Actions (inbox tab)**

- `action_harvest` — `@work` async worker: run the harvest flow for the cursor session (reuse `harvest`'s distill → `_render_md`), inspect the digest: empty (no summary + empty lists) → `archive_thread` the session; else `write_harvest` + `mark_harvested`. - `action_snooze` — push a `ModalScreen` with an `Input`; on submit, `parse_duration` (invalid → error in the modal, no close); on success `snooze_thread(..., until=…)`, save, remove the row.
- `action_select_day` — `select_for_day(reg, id, today)`, save, remove from inbox (it's now in *selected*).
- `action_detail` — push a detail `ModalScreen` (project/status/whatItIs/last prompt/branch + `export.render_conversation`); its own binding `h` pops back.
- **On exit** (`on_unmount` / a quit action): apply `_staged_deletes` via `prune.delete_sessions` (or the per-session delete path), save. (For v1 a confirm-count print on exit is fine; a modal confirm can come later.)
