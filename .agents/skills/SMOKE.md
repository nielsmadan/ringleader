# Smoke checklist

The nine `ringleader-*` skills (`ringleader-overview`, `ringleader-init`,
`ringleader-triage`, `ringleader-cleanup`, `ringleader-usage`, `ringleader-finish`,
`ringleader-publish`, `ringleader-analyze`, and `ringleader-recommend`) are markdown (agent-driven flows over the `rl` CLI), so there's no
unit-test harness for them —
`just test` covers `rl` itself. This is a manual run list for exercising the skills end to
end before a release. Each row gives the command(s) to run and what "working" looks like.

`just sandbox` runs `rl install skills --yes` before opening the test shell, so the
bundled skills are reachable by the agent launched there. Run `rl doctor` to inspect the
links; `rl update skills` re-syncs after the bundled set changes, and `rl uninstall
skills` removes the symlinks this tool created.

Reset the frozen sandbox, then enter its isolated shell:

```sh
just sandbox-reset
just sandbox
```

The sandbox contains 100 privacy-reviewed, verbatim OSS sessions and an empty registry.
Every command below then reads and writes only `.sandbox/`; exit the shell and run
`just sandbox-reset` between scenarios to return to the same zero state.

| # | Skill / behavior | Command(s) | Expected observable |
|---|---|---|---|
| 0 | `rl install skills` wires the skills up, `rl doctor` reports it | `rl install skills --yes`, then `rl doctor` | `install` symlinks the bundled `ringleader-*` skills into `~/.claude/skills`, `~/.agents/skills` and/or `~/.factory/skills` for each detected agent and reports how many it linked; `rl doctor` lists each detected agent's skills dir with every `ringleader-*` skill marked `linked`. |
| 1 | `ringleader-overview` renders and offers triage | `rl overview` (or `--registry <tmp>` against a registry seeded with a session whose `lastActive` is >24h old and not yet triaged), then `rl triage --json` | Overview prints the project rollup with the `⚠ N awaiting triage` header; the >24h-old, undecided session shows up in the `rl triage --json` inbox, and the `ringleader-overview` skill's Step 2 surfaces its count and offers to drop into triage before continuing. |
| 2 | `ringleader-triage` completes a small scope end-to-end | `rl triage --recent 3 --registry <tmp-registry> --json`, then drive the `ringleader-triage` skill against that registry: `rl prune --registry <tmp-registry>` (preview), per-session `rl session set --session <id> --status ... --what ... --name ...` or `rl session delete <id>`, `rl session name --registry <tmp-registry>`, `rl session mark reviewed <id>`, `rl session mark cleaned <project>` | The 3-day inbox empties: `rl triage --recent 3 --registry <tmp-registry> --json` returns `[]` afterward, and `rl overview --registry <tmp-registry>` shows the project's `cleaned` column updated to today. |
| 3a | harvest writes to a clean checkout | Pick a finished session whose repo checkout (`rl overview --checkouts`) has a clean `git status`; run the harvest sub-protocol's extract + synthesize steps, writing doc edits directly into that checkout | `git status` in the checkout shows the new doc edits as uncommitted changes (nothing committed on the user's behalf); `rl session mark harvested <id> --paths <doc paths>` then `rl session archive <id> --summary-file <notes path>` succeed. |
| 3b | immediate triage integration skips a dirty checkout | Same as 3a but against a repo whose checkout has uncommitted changes (or no checkout at all) | The skill reports the dirty, missing, or ambiguous checkout without writing anywhere; it creates no worktree and leaves the original checkout unchanged. |
| 4 | `ringleader-init` verifies the CLI, reports retention, and runs a bounded pass | In the sandbox shell, run `rl --help` (or `uv run rl --help` from a source checkout) to confirm `rl` resolves, then `rl doctor`, `rl overview --json`, `rl prune`, and `rl triage --recent 7 --json` before invoking `ringleader-init` | `rl doctor` warns that Claude Code's `cleanupPeriodDays` is 7; overview contains exactly 100 sessions, split 70 Claude Code / 30 Codex; prune previews exactly ten stale tiny sessions; the 7-day triage scope contains exactly eight sessions. The skill hands off to that small, finishable first pass. |
| 5 | `ringleader-cleanup` resumes on re-run | Run the `ringleader-cleanup` skill against a registry with a multi-project backlog, stop partway through (after at least one `rl session mark cleaned <project>`), then invoke `ringleader-cleanup` again | The second run's inbox (`rl triage --registry <tmp-registry> --json`, no `--recent`) no longer includes sessions already marked `reviewed`/`harvested`, and projects already marked `cleaned` aren't re-presented — the run picks up from where the first one stopped instead of restarting the whole backlog. |
| 6 | `ringleader-publish` drains a collection safely | With temporary state and two local repositories, create pending items for a dirty repository, a clean changed repository, and a clean no-change group; interrupt once after the changed commit before consumption, then rerun from the collection root | The dirty repository is skipped unchanged; the changed repository receives exactly one local `chore: update docs` commit; the no-change group receives no commit; exact handled queue items disappear only after verified integration; the interrupted receipt recovers without a second commit; no push occurs; and the final report names every retained group. |
| 7 | `rl session whoami` recognises the agent it's running inside | In each of the four probeable agents (Claude Code, Codex, OpenCode, Pi — droid is out of scope, it exports no session-id variable), run `uv run rl session whoami`. Where it prints `not inside a recognised agent session` (exit 1) instead of `<source> <id>` (exit 0), run `env \| grep -iE "session\|thread"` in that same agent shell, find the variable holding the session/thread id, and add a `"<source>": "<VAR_NAME>"` entry to `PROBES` in `ringleader/session_env.py`; re-run `uv run rl session whoami` to confirm it now resolves. | Claude Code: verified — `CLAUDE_CODE_SESSION_ID` resolves today (`claude-code <uuid>`, exit 0). Codex, OpenCode, Pi: unverified as of this row — each needs a human to drive the agent interactively and fill in its `PROBES` entry per the procedure above. |
| 8a | `ringleader-finish` harvests and marks the current session, then `roundup` archives it | Inside a live agent session in the sandbox, invoke the `ringleader-finish` skill: `rl session whoami`, then `rl session harvest --current --from-file -` with a short markdown harvest, then `rl session finish --current`; afterward run `rl harvests` and `rl roundup --registry <tmp-registry>` | `rl harvests` lists the new harvest; the session's registry entry shows `finishOnExit: true`; `rl roundup` (or `rl session sweep`) archives the transcript once it's quiet, and the session no longer appears in `rl triage --json`. |
| 8b | `ringleader-finish` finishes a session with nothing to keep, writing no harvest | Inside a live agent session whose work was pure housekeeping, invoke `ringleader-finish` and pick *Finished, nothing to keep*: `rl session whoami`, then `rl session finish --current --force` with no `rl session harvest` call; afterward run `rl harvests` and `rl roundup --registry <tmp-registry>` | `rl harvests` count is unchanged and no harvest names this session; the registry entry shows `finishOnExit: true` with `decision` unset; `rl roundup` archives the transcript once it's quiet and the session no longer appears in `rl triage --json`. Without `--force`, `rl session finish --current` refuses it. |
| 9a | Claude Code's session-end hook archives without a roundup | With `HOME` scoped to a throwaway dir (never the real one), run `HOME=<tmp> rl install hooks --yes`; inside a real Claude Code session started with that `HOME`, invoke `ringleader-finish` end to end, then quit the agent | `HOME=<tmp> rl doctor` reports Claude Code's hook `installed`; within seconds of quitting — no `rl roundup` run — the session's transcript has moved into `archive/`. |
| 9b | Codex's session-end hook archives without a roundup | Same procedure as 8a, `HOME=<tmp> rl install hooks --yes` inside a real Codex session started with that `HOME` | `HOME=<tmp> rl doctor` reports Codex's hook `installed`; the transcript is archived seconds after quitting, without a roundup. |
| 9c | Pi's session-end hook archives without a roundup | Same procedure as 8a, `HOME=<tmp> rl install hooks --yes` inside a real Pi session started with that `HOME` | `HOME=<tmp> rl doctor` reports Pi's hook `linked`; the transcript is archived seconds after quitting, without a roundup. |
| 9d | Droid's session-end hook archives without a roundup | Same procedure as 8a, but isolate droid with `FACTORY_HOME_OVERRIDE=<tmp>` as well as `HOME=<tmp>`: run `HOME=<tmp> FACTORY_HOME_OVERRIDE=<tmp> rl install hooks --yes`, inspect the written `<tmp>/.factory/hooks.json`, then invoke `ringleader-finish` inside a real droid session started with the same environment and quit | The written file is keyed by event name **directly** (`{"SessionEnd": [...]}`), not nested under `hooks`, with `"timeout": 5`; `rl doctor` reports droid's hook `installed`; the transcript is archived seconds after quitting, without a roundup. Then `rl uninstall hooks --yes` **removes the file** rather than leaving `{}`. If `<tmp>/.factory/hooks/hooks.json` existed instead, install writes into *that* file and creates no `hooks.json`. |
| 10a | `rl resume` re-enters a session in its own agent | In the sandbox, `cd` into a directory that has sessions and run `uv run rl resume`. Check `ctrl+j`/`ctrl+k` move the highlight, type a few characters and confirm the list filters and the query survives `ctrl+k`, press `ctrl+r` then `ctrl+a` and watch the row count grow. Pick a session, choose its own agent, and let it launch. | The picker opens instantly (before any scan finishes). The chosen agent starts **in the session's directory** and resumes that conversation rather than a new one. `rl resume <id-prefix> --dry-run` prints the same directory and argv without launching. |
| 10b | `rl resume --to` hands a session to a different agent | `uv run rl resume <id-prefix> --to codex --dry-run`, then re-run it without `--dry-run`. | The dry run prints `would write:` and leaves `~/.local/share/ringleader/handoffs/` absent; the real run writes one owner-only (`0600`) Markdown transcript there and launches Codex with a prompt naming the original agent and pointing at that file. The source session's registry entry is unchanged and it is still listed by `rl resume`. |
| 10c | `rl resume` refuses safely when it cannot launch | Try each of: an id that does not exist; an id that is archived; a session whose directory you have since deleted; `--to emacs`. | Each exits non-zero with a message naming the fix (`rl session unarchive <id>`, `rl workspace retarget`, the list of valid agents). None of them launches an agent or changes directory. |
| 11 | Droid sessions are scanned, resumable, counted and archived whole | On a machine with real droid history: `rl overview --source droid --sessions`, `rl usage --source droid --all --by session`, `rl resume <droid-id-prefix> --dry-run`, then archive one finished droid session and inspect the archive directory | Overview lists only **top-level** droid sessions — subagent threads (those carrying `callingSessionId`) never appear, so the count is far below the file count under `~/.factory/sessions`. Usage reports totals with **no cost column** for droid (Factory bills credits; nothing is priced), one record per session. The dry run prints `droid resume <id>` and the session's own directory. The archive holds the transcript **and both** `<uuid>.settings.json` / `.settings.json.bak` sidecars, and `rl usage --archived --source droid` still counts it. |
| 12a | `ringleader-analyze` hands a cold index to the user | With no analysis index built, drive `ringleader-analyze` inside an agent | `rl analyze --json --no-refresh` exits 3; the skill says the index isn't built, tells the user to run `rl analyze` in a terminal, builds nothing and stops. |
| 12b | `ringleader-analyze` writes a findings report | With the index built (`rl analyze` run once in a terminal), drive `ringleader-analyze` over the last 7 days | The skill reads the worst sessions and their episodes, passes no `--label`, and saves a report via `rl analyze reports save findings -`; `rl analyze reports --kind findings --json` lists it with its window. |
| 12c | `ringleader-recommend` cites its findings and edits nothing | After 12b, drive `ringleader-recommend` | A report is saved with `rl analyze reports save recommendations - --based-on <id>`; its `based_on` names the findings report; no skill, instruction or config file changes (`git status` in the repo and `~/.claude` is clean of edits). |
